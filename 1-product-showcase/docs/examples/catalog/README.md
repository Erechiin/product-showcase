# Jonathan Sales Programming

Coleção de atividades práticas de programação para pessoas com diferentes níveis
de experiência. Cada aluno cria sua versão no próprio repositório. Na aula,
seguimos as mesmas etapas juntos e deixamos o acabamento individual para depois.

**[Abra a lista de atividades em projects/](projects/README.md).**

## Como participar

1. Escolha uma atividade disponível.
2. Abra o link do esqueleto.
3. Leia o README e faça a preparação antes da aula.
4. Faça fork para sua conta e escolha o nome do projeto.
5. Clone seu fork e abra a pasta no VS Code.
6. Siga o roteiro guiado do projeto, aguardando nas pausas combinadas.
7. Personalize, confira, faça commit e push.
8. Entregue a URL do próprio fork e os itens pedidos.

Este repositório é o catálogo. O código de cada atividade fica em outro
repositório, indicado na lista. Faça fork do esqueleto da atividade.
Não é necessário abrir pull request para o professor.

## Organização e idioma

O nome genérico do primeiro esqueleto é `1-product-showcase`. Seu fork pode se
chamar `1-book-store`, `1-anna-sweets` ou outro nome com o número da atividade.
Na próxima atividade, você fará outro fork do novo esqueleto.

No computador, pode organizar assim:

```text
jonathan-sales-programming/
└── projects/
    ├── 1-book-store/
    └── 2-my-menu/
```

As pastas externas são organizadoras, sem Git. Cada projeto é um clone independente.
Essa estrutura local não representa repositórios aninhados no GitHub.
Para editar este catálogo, use uma pasta separada dos projetos.

Código, comentários, interface, arquivos e nomes de repositório ficam em inglês.
README e guias de construção ficam em português para facilitar o acompanhamento.

## Uma base comum

Cada pessoa escolhe tema e aparência, preservando a lógica do esqueleto durante
o roteiro coletivo. Nas etapas de frontend, faremos só as primeiras alterações
juntos. Fotos restantes, fontes, espaços e outros detalhes serão concluídos depois.

As próximas atividades seguirão o mesmo ciclo de preparação, execução,
pequenas mudanças, verificação, commit e push. Mudanças de lógica ficam como
extensões conscientes para depois da trilha comum. Atividades em preparação
ainda não estão liberadas.
